# GS Manpower Services – website handoff

Six-page corporate website (plus a privacy notice and an internal component library) for GS Manpower Services,
Chhatrapati Sambhajinagar. Static HTML/CSS/JS, no runtime dependencies, generated by a ~100-line Node build script.

## Run it

```bash
npm run dev        # build, serve http://localhost:4173 and rebuild when anything in /src changes
npm start          # build once and serve
npm run build      # build only; deploy the /site folder
```

Node 18+ required. Nothing to install (`npm install` is not needed). If port 4173 is busy: `set PORT=4174` then `npm run dev`.

## Structure

| Path | What it is |
|---|---|
| `src/content/site.json` | **Edit this first.** Phone, WhatsApp, email, address, hours, form endpoints, GA4 ID, base URL, feature flags |
| `src/layout.html` | Page shell: meta/SEO tags, JSON-LD, fonts, scripts |
| `src/pages/*.html` | One file per page. First line is `<!--meta {json}-->` (slug, title, description, noindex) |
| `src/partials/*.html` | Header, footer, icon sprite, consent banner, the two forms. Included with `{{> name}}` |
| `src/assets/css/tokens.css` | Design tokens (colour, type, space, radius, shadow). Mirror: `src/assets/tokens.json` |
| `src/assets/css/styles.css` | All components, mobile first (breakpoints 640 / 960 / 1024 px) |
| `src/assets/js/main.js` | Mobile nav, form validation + submission, consent-gated analytics |
| `src/static/_headers` | HTTPS/HSTS, CSP and caching headers (Netlify / Cloudflare Pages format) |
| `site/` | Build output (git-ignored) |

Template syntax: `{{key}}` from site.json or page meta, `{{> partial}}`, and
`<!-- if:flag --> … <!-- endif:flag -->` kept only when `features.flag` is true. The build fails on any unfilled `{{…}}`.

## Pages

Home (`index.html`), About Us, Our Services, Industries, For Job Seekers (`careers.html`), Contact Us,
plus Privacy Notice and `components.html` (component library, `noindex`, excluded from sitemap/robots).

Homepage order follows the brief: hero with Hire Manpower / Find a Job → verified trust indicators → service cards →
why GS Manpower → how it works → industries → training and quality → enquiry form → footer.

## Design system

Source of truth: **GS Manpower Brand Guidelines v1.0 (October 2026)**. It supersedes the palette and fonts in the
original design brief.

- **Palette:** Command Navy `#14213D` (primary), Shift Saffron `#F2A007` (accent), Site Paper `#F6F4EF` (ground),
  Steel `#5B6477` (secondary text), Care Teal `#0E7C70` (GS Care division only). Proportion 60 navy / 25 paper-white /
  5 steel / 10 saffron. Derived shades in `tokens.css` are for states and contrast only.
- **Saffron rules:** a signal, not a background. Use it for the figure in the mark and **one** call to action per
  layout (`.btn-primary`, navy text on saffron). Other solid buttons use `.btn-navy`. Never saffron text on white/paper.
- **Type:** Archivo 800/900 for headlines and the wordmark (H1 40/44, H2 24/30), Manrope 400–700 for body (15/24) and
  labels (700, caps, +16% tracking), Mukta 600/800 for all Devanagari. Never letter-space Marathi or Hindi.
- **Logo:** the "G Guardian" mark (navy G around a saffron worker). Files in `src/assets/img/`: `gs-mark.svg`,
  `gs-mark-reversed.svg` (footer), `gs-mark-care.svg` (GS Care), `gs-mark-mono-black.svg`, `gs-mark-mono-white.svg`.
  **These are an interim redraw** from the guideline pages. Replace them with the master `GS_Manpower_Mark.svg` / logo
  files when supplied (keep the same file names). Header uses the primary horizontal lockup (mark + GS MANPOWER +
  STAFFING · HEALTHCARE · INDUSTRY), footer the reversed one. No shadows, effects, recolouring or retyping. The
  descriptor drops below 360 px screen width.
- **Divisions:** GS Care (teal G) and GS Industrial (navy G). The site uses the master logo; division marks label the
  division sections on Home and Services.
- **Voice:** plain, punctual, provable. Promise only numbers the company keeps (replacement in 24 hours, PF/ESIC
  compliant, police-verified). Never "best", "No. 1" or "world-class". Client pages lead in English; the job-seeker
  page leads in Marathi with a Hindi line for MIDC migrant workers.
- Status is always colour + icon + word. No exclamation marks or emoji in copy.
- Components (see `/components.html`): buttons, link-arrow, card / card--link, tile, feature, trust item, badge,
  notice, steps, photo placeholder, CTA band, form fields, choice chips, consent banner, header, footer, WhatsApp float.

## Security service – licence gate

Security guarding needs a PSARA 2005 licence from the Maharashtra controlling authority. All security content
(home card, services section, footer link, form options) is wrapped in `<!-- if:security -->`. It stays out of the
built site until `features.security` is set to `true` in `site.json`, **after** the licence is granted. Then fill in
the licence number in `services.html`.

## Forms – what the backend must do

The two forms (`employer-enquiry`, `job-application`) POST `multipart/form-data` to `enquiryEndpoint` /
`applicationEndpoint`. With no endpoint set they run in **preview mode**: validate, show success with a
"nothing was sent" note. Fields are named in the partials; `form_name`, `started_at`, `company_website` (honeypot)
are included on every submission.

Endpoint requirements:
1. HTTPS only; reject requests whose `company_website` is filled or whose `started_at` is < 3 s ago.
2. Server-side validation mirroring the client (required fields, phone pattern, file type .pdf/.doc/.docx, ≤ 5 MB,
   and check file magic bytes; never trust the extension).
3. Rate-limit per IP; add Cloudflare Turnstile or hCaptcha if spam appears (CSP must then allow its domain).
4. **Secure storage:** private bucket / database with encryption at rest, access limited to named staff, resumes
   never publicly addressable. Retention: enquiries 24 months, applications 12 months (matches the privacy notice).
5. **Lead notifications:** email to the business inbox and/or WhatsApp Business API template message to the owner.
   Do not put applicant personal data in the notification body; link to the stored record instead.
6. Return 2xx JSON on success; any non-2xx shows the "call us" fallback.
7. Add the endpoint's domain to `connect-src` in `_headers` if it is not same-origin.

Options: a serverless function on the same host (Netlify/Cloudflare/Vercel functions) writing to an encrypted store,
or a reputable form service with an Indian/EU data-processing agreement.

## Analytics with consent

Set `ga4Id` in `site.json`. Nothing loads and no banner shows until an ID is set. Once set, the banner appears with
equal-weight Decline / Allow buttons; GA4 loads only after Allow (stored in `localStorage`), with ad storage denied.
Footer "Cookie preferences" reopens the banner. Events sent: `generate_lead` (form success), `contact_whatsapp`.

## Hosting, HTTPS, performance

- Deploy `/site` to Netlify or Cloudflare Pages (automatic HTTPS; `_headers` is picked up). On other hosts, port the
  headers. Point the domain, then update `baseUrl` and rebuild (canonical URLs, sitemap, robots, JSON-LD).
- Self-host Manrope/Inter (woff2, subset Latin + Devanagari) to drop the Google Fonts request; then tighten CSP.
- Photos: serve AVIF/WebP via `<picture>`, explicit width/height, `loading="lazy"` below the fold, hero ≤ 150 KB.
- Current build: ~35 KB CSS, ~10 KB JS (unminified), no framework. Target Lighthouse mobile ≥ 95 performance and 100 accessibility.

## Content management (CMS)

Today content lives in `site.json` and the page files (git-based editing). Recommended next step for non-technical
editing: **Decap CMS** (free, git-based) editing `site.json` and Markdown/JSON content collections, deployed with
Netlify Identity; or a hosted headless CMS (Sanity, Storyblok) if the team wants a richer editor. Either way, keep the
build script as the renderer so the design system stays intact.

## Accessibility

Skip link; landmark roles; visible focus ring; 48 px touch targets; mobile menu with `aria-expanded`/Escape;
form labels, required/optional text, inline errors linked by `aria-describedby`, `aria-invalid`, focus moved to the
first error and a status message; `prefers-reduced-motion` respected; colour contrast AA.
